# 开发问题记录模板

日期、工程版本（基于哪个提交）、对象与文件：

协助工具：Codex / Claude Code（写实际参与的那个，两者都参与时分别注明各自的建议）

相关 Issue：#N（没有就写“无”）

## 用户观察与目标

记录用户实际观察到的现象和希望得到的行为。少量必要原话注明来源为当次聊天，不补造测试。

## 用户提出的想法

按讨论顺序记录用户的判断、假设、疑问和实现思路，包括未最终采用的方案及其取舍。用户后来补充的思路及时追加。

## 辅助分析与建议

写明协助工具（Codex 或 Claude Code）根据哪些文件或证据作出分析，以及给出什么建议。区分建议、被否定的假设与已核实原因，不将双方贡献混写。

## 实际采纳与用户调整

记录用户采用哪一部分、独立增加哪些条件或设计、实际变量名与资源名。最终未采用的候选方案标为历史建议。

## 验证与当前状态

分别列出用户完成声明、静态文件核验、实际运行结果、待验证事项；只有取得证据的结果才写为完成或通过。待验证事项同时开 GitHub Issue（标签 `待验证`），在这里写上编号。

## 论文素材与证据入口

说明该案例可支持的设计取舍、实现流程和问题解决过程，链接代码、配置、原始测试记录或用户反馈。避免将第三方机制写成原创技术，不生成虚构数据。
