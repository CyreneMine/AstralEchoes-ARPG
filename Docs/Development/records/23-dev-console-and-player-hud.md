# 管理员控制台、运行时属性与玩家血条

日期：2026-10-29 实施，2026-10-30 归档。Unity 6000.4.8f1；GMScene。

2026-11-10 按用户要求撤回部分配套实现，下文保留当时历史。当前代码与待接回功能见[撤回记录](29-console-support-code-removal.md)。

## 用户观察、目标与想法

用户希望先制作基础游戏主界面，最基本的是玩家血条。随后明确委托 Codex 在场景已有 Canvas 下搭建 DevConsole，要求提供扣血、回血、杀死玩家和实时改属性。用户自行创建过 DevConsole、PlayerHealthBar 文件；本轮具体控制台和生命/HUD 联动由 Codex 在授权范围内实现。用户后续新增“清空玩家任务存档”需求，另见独立记录。

## 辅助分析与建议

角色 SO 配置被多个角色共享，调试时直接改共享数据会影响资源或其他实例，因此 CharacterObject.Init 从配置条目创建运行时副本。当前生命值、最大生命、防御与死亡状态由 CharacterHealth 持有；HUD 订阅生命变化事件，不在 UI 中计算伤害或修改 SO。

初次检查已有场景 HUD，但 UIManager 总是创建另一份 Canvas。改为优先接管场景已有屏幕空间 Canvas 和相应面板；没有场景对象时继续加载原 Resources 预制件。此为避免既有 HUD 被新实例覆盖的最小改动，没有重写 UI 框架。

## 实际实现与用户独立调整

- `CharacterHealth` 增加 HealthChanged、直接扣血、回血、设置当前血量、更新最大生命与防御；血量限制在合法范围。原伤害经防御后不小于0。
- `CharacterObject` 公开 Health，初始化独立 CharacterData 副本，提供 SetRuntimeAttributes。
- `PlayerHealthBar` 绑定生命事件，使用浮点比例刷新 Filled Image 和数字，最大生命不大于0时显示0，禁用时解除订阅。
- `PlayerObject` 与 `PlayerCombat` 的 Update 增加死亡状态判断。没有制作新的死亡动画。
- `PlayerHealth` 的 CharacterHealth 继承和 TakeDamage override 是用户修改；用户自行将未完成的 public 行注释，本轮没有把该操作归为 Codex 修复。
- `DevConsole` 用新输入系统读取 F1/Esc；打开时暂停此前启用的角色移动/攻击组件和相机输入，关闭后恢复对应组件及光标状态。
- 原控制台20个按钮覆盖固定/自定义扣血回血、防御伤害测试、满血、杀死/复活、属性输入及微调、恢复SO初值与窗口开关。后续再增加1个清空任务存档按钮。

Editor 搭建工具生成可直接编辑的序列化 UI、文本和持久回调。字体最初出现缺字，改为从工程已有中文字体源创建独立动态字体资产；没有购买/下载新美术。新资源仍只保留本地，工程恢复时需要补回。为仓库可迁移，收尾仅把两个自编 Editor 工具的报告目录改到工程 Temp 下，不改玩法逻辑。

## 验证与当前状态

2026-10-29 的实际 Play Mode 检查通过了10项：扣血、回血、杀死、复活、属性、防御伤害、HUD、重置、共享配置隔离、关闭恢复输入。测试通过调用已序列化按钮的 UnityEvent 执行，不等于鼠标逐一点击或 F1/Esc 按键验收。

其中属性设为攻击7/防御4/最大生命80后，施加14原始伤害得到70生命；HUD比例0.875、文字70/80，验证数值与显示一致。该数值来自已保存的运行报告和检查代码，不是新增统计实验。

最后一次本机鼠标/键盘验证被用户 Esc 停止，未完成。因此 F1/Esc 和原生鼠标操作仍需独立验收。10月30日清空任务存档按钮已完成编译与绑定检查，没有替用户执行清空。收尾仅静态归档，未重做 Play Mode 或构建，不把旧测试扩大为最新全模块验收。
