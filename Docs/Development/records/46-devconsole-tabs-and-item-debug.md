日期：2026-11-21 实施，2026-11-22 验证、修改并提交。工程版本：基于 `21822fa`，本次提交 `7269797`（控制台脚本）、`b3c303d`（编辑器工具）。

协助工具：Claude Code。控制台由 Claude Code 维护（见[记录 29](29-console-support-code-removal.md)），只适配用户的接口，本次没有修改任何玩法脚本。

相关 Issue：#30（11-22 修改后的复测）、#25（简单背包与道具表，本记录只提供调试工具，不包含背包本身的验证）。上一次控制台改动见[记录 39](39-devconsole-level-controls.md)。

## 用户观察与目标

11-21 用户单独开了一个专门管理控制台的会话，提出：

> 给控制台加入一个给玩家添加指定道具的功能（比如可以先选择要添加什么物品，也可以直接输入物品 ID），还有如果你觉得目前的控制台展开布局不适合你，可以完全重构当前控制台和 UI。

目标是背包、上限、奖励结算开发期间，不用靠打怪或做任务攒道具，就能直接给玩家加减道具。

## 用户提出的想法

- 道具既能从列表选择，也能直接输入物品 ID。
- 授权完全重构控制台的布局和界面。
- 11-22 用户运行自动检查后看截图发现：控制台开关按钮"管理员控制台 · F1"压在 HUD 右上角的"背包"按钮上，控制台关闭时可能挡住背包按钮的点击。要求只改控制台代码调整位置，不动 HUD。

## 辅助分析与建议（Claude Code）

### 布局重构

- 旧控制台是一整列控件，加上等级调试后窗口约 960 高，再加道具区放不下。改为 900×700 的窗口：顶部常驻状态栏（名称、等级、经验、存活、货币持有量、生命、攻击、防御），左侧四个分页（生命、属性·等级、道具、存档），底部提示栏。
- 界面从"编辑器工具生成进预制件"改为"`DevConsole.Awake` 中由代码生成"。理由：调试工具通常整套放在一个仓库里的脚本中；原来的做法依赖不入库的本地 `Canvas.prefab`，每加一组控件就要再写一个补预制件的菜单，预制件和代码容易对不上。取舍是布局只能改代码，不能在编辑器里拖。
- 预制件里旧版的 `Window`、`ToggleButton` 在运行时自动移除；编辑器菜单 `Remove Legacy Layout` 可以从预制件里删掉。删除前已把本地 `Canvas.prefab` 备份到 `Backups/DevConsole-legacy-20261121/`（不入库）。
- 生命、属性、等级、清空任务存档的逻辑与[记录 36](36-devconsole-retest.md)、[记录 39](39-devconsole-level-controls.md)相同，只改了界面组织。

### 道具分页

- 左侧列出 `ItemDatabase` 全部物品（图标、`#ID 名称`、类型、持有数量 / 上限），带按名称或 ID 搜索；点击行或在 ID 框直接输入，详情区和高亮同步。数量可输入，也可点 ×1、×10、×100、×999。
- "加入背包""扣除"调用用户的 `PlayerItemMgr.AddItem` / `RemoveItem`；"按奖励结算"调用 `RewardMgr.SettlementReward`，用来检查结算分支。
- 控制台打开期间订阅 `OnItemCountChanged`，任何来源改了数量，列表和详情都会刷新，关闭时取消订阅。
- 规则上的取舍：
  - 配置表外的 ID 不允许添加，否则背包格子取不到配置会空引用；扣除只要求 ID 合法，方便清理存档中没有配置的旧记录。
  - 经验类物品不能加入背包（[记录 37](37-inventory-and-reward-design.md)的设计约定），提示改用"按奖励结算"。
  - 数量相加会超出 `int` 上限时拒绝。
- 存档分页新增"清空背包道具"：对每条持有记录调用 `RemoveItem` 扣到 0，由 `PlayerItemMgr` 自己删除记录、广播、存盘。两个清空按钮都改为 3 秒内点两次才执行。

### 11-22 跟进用户接口的变化

11-21 写完后，用户在 11-22 完成了 `maxCount` 截断、`RewardMgr` 非经验类型进背包、背包订阅数量变化刷新（[记录 43](43-bag-slot-display-and-refresh.md)、[记录 45](45-item-cap-reward-and-mission-settlement.md)）。控制台随之调整：

- 加入或结算后实际增加量少于请求数量时，提示"达到上限，实际增加 N，多出的被丢弃"；已在上限时结算，提示没有增加。
- 删掉"背包面板正开着，请关闭后重新打开"的提示，因为 `BagPanel` 已自己订阅 `OnItemCountChanged`。
- 自动检查里"按奖励结算非经验物品"从只记录现状改为判定：持有数量 +1（有上限时不超过上限）。

### 开关按钮位置

- 从 `GamePanel.prefab` 读到右上按钮栏 `Right_Up` 锚定右上角，高 149，背包按钮宽约 132、在最右侧。原开关按钮在 y 18～60，正好压在背包按钮上；展开的窗口从 y 70 开始，也会盖住它。
- 开关按钮下移到按钮栏下方（y 161～203），窗口跟着下移到 y 211～911，在 1080 参考高度下不碰底部血条（顶边约 y 918）。数值写成常量 `HudTopBand = 149`，代码注释说明 HUD 布局改动后要同步。
- 自动检查新增一项：开关按钮的屏幕矩形与 HUD 上任何按钮都不重叠，否则判失败；展开后的窗口只记录是否重叠，不判失败。
