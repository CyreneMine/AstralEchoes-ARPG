# NPC 首次交互提示卡顿与启动预热

日期：2026-10-29 讨论、用户修改并确认；2026-10-30 归档。

## 用户观察与目标

用户发现第一次显示对话按钮时卡顿，后续多次显示均正常，即使面板每次销毁再创建也不会重复卡顿；希望在赶时间时采用最小改动。

## 用户提出的想法

用户先询问是否属于同步问题、能否用异步或协程；随后指出每次同样调用 UIManager.ShowPanel，为何只有第一次卡顿。最终用户主动提出在程序开头执行一次 Show 和 Hide 预热，并自行实现，之后反馈“这个解决了”。

## 证据分析与 Codex 建议

用户提供的 Profiler 截图中，选中帧 CPU 约103.26ms，Canvas 更新链约49ms，TMP Rebuild 约40ms，下面可见样式字典初始化和 Mono.JIT。该截图与“只有首次”现象相符，支持首次文本/样式初始化存在额外开销；不能把总帧耗时全部归于文本，也不能将嵌套样本相加当成多个独立耗时。

解释为：面板对象销毁，不意味着同进程中字体、样式、资源或已编译方法缓存同时销毁，所以新建第二个面板不一定重复首次成本。协程只把工作安排到不同帧，不会自动把 Unity UI 创建与首次渲染搬到后台线程。

Codex 曾提出显示后刷新文本/Canvas再隐藏的预热思路；用户最终采用自己的最简版本，没有加入强制刷新或协程。

## 用户采纳与当前文件依据

`Assets/Scripts/Object/NPC/TestDialogue.cs` 的 Start 调用：

```csharp
UIManager.Instance.ShowPanel<InteractPanel>();
UIManager.Instance.HidePanel<InteractPanel>();
```

这里使用现有默认淡出，未改 UIManager 的销毁规则。用户另外将 interactPanel 保存在字段中，再在靠近 NPC 时传入交互目标。原距离轮询仍保留，不把本次改动写成对象池或异步加载实现。

另有用户移除敌人血条刷新的重复 print 等调试日志；本轮原样提交该调整。未声称有已测的帧率增益。

改善结果为用户现场确认。静态核对已保存的启动 Show/Hide 代码，没有进行新的优化前后 Profiler 对比，没有发布构建或移动设备性能结论。
