## 2. 问题背景与现象

早期使用 Blender 的 mmd_tools 将 PMX 导出为 FBX。用户反馈 FBX 在 Unity 中显示为灰白色。检查发现：当时的 FBX 包含64个材质，但没有 Texture/Video 对象及相应纹理连接；当时检查的 Unity 材质已使用 URP/Lit，基础贴图槽仍为空。因此，该阶段不能仅靠更换 Shader 恢复贴图。

这部分属于**早期 FBX 检查记录**，证据为 source_evidence.json（本地文件未上传：`Cyrene材质修复/source_evidence.json`）。后续用户切换为 PMX 直接导入，本次最终修复未重新导出 FBX，也没有采用 Blender 材质重建方案。不要把早期分析脚本写成最终应用到工程的修复工具。

PMX 导入后，角色整体贴图已能显示，但出现以下异常：

- 裙子及部分衣服表面存在大量醒目的白色颗粒。
- 用户转动 Scene 镜头后反馈，颗粒完全不会闪烁或移动。
- 单独预览“裙3+”材质时也能看到相似颗粒。
- Inspector 截图显示，该材质的 Surface Type 为 **Cutout**，Alpha Clip Threshold 为 **0.01**；内嵌材质界面不可直接编辑。

## 4. 透明处理原理

Alpha Test（透明裁剪，界面中的 Cutout）先比较像素透明度与阈值，低于阈值的像素被丢弃，其余像素按不透明方式输出。阈值为0.01时，部分原本很淡的白色细点仍会通过裁剪，并以明显的实心点显示。

Alpha Blend（透明混合，界面中的 Transparent）保留像素透明度。标准混合可简写为：

```text
输出颜色 = 前景颜色 × α + 背景颜色 × (1 − α)
```

因此，本次需要保留细点本来的透明度，而不是删除贴图内容或一味提高裁剪阈值。恢复合理透明度后，装饰纹理仍可能可见；不能把“所有白点彻底消失”作为唯一正确结果。

所安装插件的关键实现如下：

- `MmdMaterialTransparencyPolicy.ClassifyTextureAlpha`：依据所采样透明度的分布，将材质分类为 Opaque、AlphaTest 或 AlphaBlend；稀疏半透明信息有可能进入 AlphaTest 分支。
- `MmdUnityMaterialBuilder`：默认裁剪阈值为0.01。
- `MmdMaterialSurfaceState.Create`：分别设置裁剪、纹理透明度输出权重及混合状态；AlphaBlend使用 SrcAlpha / OneMinusSrcAlpha。
- `MmdBasicUrpToon.shader`：通过 `clip(albedoAlpha - _AlphaClipThreshold)`执行裁剪，再依据输出权重选择透明度。

**实现细节边界：该插件当前 AlphaBlend 配置仍启用深度写入，不能把本次修复概括成“关闭 ZWrite”。**本次覆盖只指定 Surface Mode，具体状态由插件设置。

## 5. 最终修改内容

生成并绑定独立覆盖资产：CyreneSkirtAlphaBlendTest.asset（本地文件未上传：`Assets/ArtRes/Characters/Cyrene/Materials/CyreneSkirtAlphaBlendTest.asset`）。文件名保留初次单材质试验时的命名，当前已包含四条覆盖。

| PMX材质索引（从0开始） | 原始材质名 | 基础贴图 | 指定方式 |
| --- | --- | --- | --- |
| 46 | 裙3+ | 衣5.png | AlphaBlend |
| 17 | 上衣+ | 衣3.png | AlphaBlend |
| 44 | 衣+（第二个同名材质） | 衣5.png | AlphaBlend |
| 45 | 衣++ | 衣5.png | AlphaBlend |

索引依据原始 PMX 材质列表核对。尤其“衣+”存在重名，索引44与索引20不是同一个材质，不能仅凭名称把两者一起替换。更新或换用模型后，需重新核对索引。

覆盖条目的核心配置为：

```yaml
enabled: 1
materialIndex: 46
materialName: "裙3+"
matchMode: 0
hasAlphaClipThreshold: 0
hasSurfaceMode: 1
surfaceMode: 3  # MmdMaterialOverrideSurfaceMode.AlphaBlend
```

另外三条仅替换对应索引和材质名。未手动覆盖Alpha数值、贴图或Shader预设，也未把所有材质改成透明。

实际应用方式：在PMX的Materials页通过Material Override引用该资产。本次通过写入独立覆盖资产并修改PMX导入器的对应引用完成配置，随后由Unity刷新资源；没有新增自定义Editor修复脚本，也没有修改插件源码。

修改边界：

- 新增覆盖资产及其 `.meta`；PMX `.meta`首次仅变更 `materialOverrideAsset` 引用，第二轮只增加覆盖资产中的三条条目。
- 不修改原始PMX、贴图、已有材质文件、骨骼、Avatar、BlendShape和模型结构。
- 第一轮对45个原有资源文件进行修改前后哈希核对；第二轮对覆盖资产之外的92个现有文件进行核对，均未改变。两次数量不同，统计范围不同，不能相加作为模型资源数量。
- 首次绑定前的PMX元数据和第二轮扩展前的覆盖资产均已备份。

## 7. 复用与撤销

复用流程：先检查异常是否也存在于单独材质预览中，再核对材质索引、原始贴图Alpha与当前Surface Type；对有依据的叠层创建Material Override并指定AlphaBlend，先单材质对照，再扩展到同类材质。无需全量提取并手动修改几十个材质。

全部撤销：选中PMX主资源，在Materials页将Material Override清空并Apply。仅撤销第二轮：把覆盖资产Entries恢复为仅索引46。备份见 裙3透明测试目录（本地文件未上传：`Cyrene材质修复/裙3透明测试`）。后续若导入设置发生新修改，不应直接用早期整份 `.meta` 覆盖当前文件。
