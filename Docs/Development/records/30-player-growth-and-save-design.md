## 辅助分析与建议

### 配置、成长逻辑和玩家状态

Codex 建议按职责区分配置、运行逻辑与存档。这是一种常见设计方式，不代表企业项目必须采用统一框架或必须使用 SO。

- SO 保存基础数值与成长规则；每级攻击增量等可称为“每级属性成长值”。固定成长可以用参数和公式，需要逐级调数值时再考虑等级表或曲线。
- PlayerMgr 提供玩家系统入口，PlayerGrowth 负责加经验、判断升级和成长计算，角色及生命组件使用计算结果。
- PlayerSaveData 是普通 C# 数据类，保存玩家当前等级和经验。脚本放在 `Assets/Scripts/Data/Save/`，与任务存档结构集中管理；实际 JSON 通过 JsonMgr 写入持久化目录。
- 曾建议单独建立 PlayerGrowthConfig，避免通用角色数据累积玩家专用字段。目前用户仍将成长字段写入 CharacterConfig.CharacterData，独立成长 SO 只是候选建议，没有落地。

### 公式与经验含义

讨论中建议，若基础数值对应初始等级，可按以下形式计算：

```text
升级经验需求 = 初始升级经验需求 + (当前等级 - 初始等级) × 每级经验需求增量
等级基础攻击力 = 初始攻击力 + (当前等级 - 初始等级) × 每级攻击成长
```

经验表示本级已积累的进度；升级消耗本次升级所需经验，剩余经验留给下一等级，经验足够时可以连续升级。满级处理、新建存档初始化和保存时机需要在实现中明确。

以上是设计说明。当前源码使用 `level × 成长值 + 初始值`；本机 PlayerConfig 的 `initLv` 为 `0`，此时与上述公式一致。不能把该实现直接当作初始等级为 `1` 的计算方式。

### 攻击力是否存档

对于固定等级成长，Codex 建议保存决定攻击力的原始状态，例如等级，以及将来可能出现的装备和永久加成，再据此得到攻击力。当前 PlayerSaveData 只有 level、exp，未加入攻击力字段。

“计算属性”不等于每帧计算。曾建议在读档、升级、装备或 Buff 变化时重算并缓存，攻击时读取结果；这仍是建议。当前 GetAtkValue 在调用时进行简单计算，尚无属性缓存。原型中这种简单计算开销很小，不能仅因没有缓存就认定为性能问题。

永久增加攻击力的道具只是未来例子；如实现，应持久化永久增加值并参与计算，不把示例写成已完成系统。正常玩法读取共享 SO，不把每个玩家的成长结果写回配置资产。
