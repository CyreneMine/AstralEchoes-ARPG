## 用户观察与目标

- 用户的 Codex 订阅快到期，想趁这几天用它的生图功能多做些素材，问做什么合适。

## 辅助分析与建议（Claude Code）

### 素材范围

- 生图只能出 2D 图，3D 模型、模型贴图和动作都做不了。优先做演示视频里看得到、近期就要用的：Buff 图标、战斗 HUD 图标、道具图标；其次是主视觉、守桥人立绘；最后才是区域概念图和特效贴图。
- 不建议花额度的：序列帧（帧间不一致）、带中文的图（容易出错字，文字一律用 TMP）、可平铺贴图和法线贴图、面板边框（Buff 面板已用代码绘制，AI 边框不规整，难切九宫格）。
- 不生成主角图像：主角是第三方角色模型，生成图和 3D 模型对不上，在公开仓库里也会多一层二创版权问题。
- 提醒素材要能追溯来源：每张图记录提示词、日期和工具，选用后登记到 ASSET_RESTORE；用于论文和 PPT 前先问导师是否需要声明 AI 生成，至少在图注里标注。

### 提示词清单

- 按批次 B1～B7 编写，每批"风格前缀 + 内容"。道具风格对齐已有的观星币和星屑药剂；Buff 和技能图标只出黑底白图，导入时把亮度转成透明度，在 Unity 里用 Image 颜色统一染成 Buff 面板的 `#9EE6FF`，这样颜色和面板一致，也不用抠图。
- 每条注明用途、实际显示尺寸和底色（背包格子 96 × 96、详情区 140 × 140、Buff 图标 80 × 80 放在 128 × 128 的金色菱形里），预览按这些尺寸验收。
- 建议用户分批放行：先跑一条确认风格，再连续跑同风格的批次，换到插画风格时再停一次。

### 概念图对不上的原因与处理

- 原因有两个：每张图都是独立生成的，模型没有共享的地图；Claude Code 写的提示词本身也不统一——B4-1 写"塔在裂谷边的悬崖上"，B4-3 写"塔在远处很小"，B7-2 写"桥的尽头是塔"，B7-4 只写"一条虚线连接三处"。这是 Claude Code 写清单时的疏漏。
- 常见做法：场景的空间关系以关卡俯视布局图或白模为准，概念图只管氛围；要让多张概念图一致，一般先搭白模、从各机位截图，再在截图上绘制（paintover）。
- 建议布局 A：村口 → 旧桥 → 桥尾台阶 → 塔前圆形庭院 → 观星塔，桥直接通到塔所在的悬崖。理由是剧情草案本来就写"三个相连的区域"，少搭一段场景，也和选定的主视觉一致。只重出村口图和地图（B7-1b、B7-4b），带上 B4-1 v1 作参考图，并在提示词开头加一段固定布局描述。
- 重出后核对：村子、桥、台阶、庭院、塔的顺序与主视觉一致，塔的造型也一致。俯视地图 B7-4b v3 最适合作为摆白模的布局参考。仍有的出入：B7-2 在桥中段画了加宽的战斗平台，地图上的桥是等宽的，摆白模时由用户决定。

### 图片处理与导入

- **Buff 图标**：把 B1-1 v2 切成三张，亮度转透明度，按实心面积补偿剑的视觉大小，输出 256 × 256。第一版按面板参数预览时，盾和心压到菱形内侧的细金线，于是把内容缩小一档。按 Buff id 命名为 `Icon/Buff/0.png`～`2.png`。
- **道具图标**：去掉离主体较远的淡抠图残留（放大对比过，柔光和星点没有被删掉），按主体裁切，主体约占画布 90%，与星屑药剂的留白接近，输出 512 × 512。按英文道具名命名：英文文件名在版本控制、打包和其他工具里更不容易出编码问题。
- **导入设置**：每张图先写 `.meta` 再放 PNG，`.meta` 除 GUID 外与 `Icon/Item/1.png` 相同（Sprite Single、Alpha Is Transparency），开着的 Unity 刷新时直接采用。
- **接入前提**：`BuffConfig` 没有图标字段。按 Buff 显示不同图标，需要用户加 Sprite 字段并在 `BuffOption` 里赋值，这部分是玩法代码，由用户编写。不要覆盖 `BuffStar.png`：一是三张卡仍会是同一个图标，二是 `BuffPanelSetup` 重新生成时会把它画回来。

- 中文按 Unity 的写法转成 `\uXXXX`，追加在原有三条之后，原有条目不动。

### 过程中的失误

- 用 sed 改本地生成记录时，路径里的 `\U` 被当成"转大写"指令，那一格变成乱码。随后按字节重写了那一格，整份文件重新核对为合法 UTF-8，其他行不受影响。只涉及本地文件，不涉及仓库。

## 实际采纳与用户调整

- **导入的图标**：B1-1 v2 → `Icon/Buff/0.png`（星锋）、`1.png`（星盾）、`2.png`（星息）；B2-1 v1 → `EngravedKey.png`，B2-3 v1 → `EchoShard.png`，B2-4 v1 → `RepairRope.png`，B2-5 v1 → `LargeStardustPotion.png`，B2-6 v2 → `StarChartScrap.png`，均在 `Icon/Item/` 下。星图残页用户没有指定版本，Claude Code 选了 v2，说明了可以替换。
- **道具表**：ID 3～7 按上表写入 `ItemDatabase.asset` 并绑定图标，由 Claude Code 按用户要求编写。
- **命名规则**：用户决定道具图标按名字命名、在 SO 里绑定；采用英文名是 Claude Code 的建议。原有的 `1.png`、`2.png` 保持不变。
- **场景布局**：用户把布局 A 的提示词交给 Codex 重出，看过结果后回复"可以"。布局和守桥人设定（男性老者，年龄不明）写入了剧情设计文档；守桥人其余外貌是 Claude Code 拟的，标为未定稿。
- **立绘**：用户决定只要一张半身像，不做多表情（原清单的 B5-2 是三种表情）。
- **未导入**：铜钟碎片、主视觉、加载图、游戏图标、特效贴图、概念图和守桥人立绘都只在本地素材目录，等对应功能开始时再导入。开始界面、特效、对话立绘都还没做。

## 验证与当前状态

- **静态核验**：PNG 尺寸和四角透明度；`.meta` 导入设置与 `1.png` 逐行比较一致；道具表中五个图标的 GUID 逐一对上对应 PNG；`git diff` 显示 `ItemDatabase.asset` 只追加 30 行；解码后的名称和描述逐条核对。
- **编辑器导入**：Editor.log 中有 `Icon/Buff/0.png`～`2.png` 和五个道具图标的 TextureImporter 导入记录，GUID 与预先写入的一致；修改后的 `ItemDatabase.asset` 由 NativeFormatImporter 重新导入，文件修改时间仍是写入时间，Unity 没有覆盖它。日志中只有原有的 CS0618 过时 API 警告，没有错误。
- **未测**：新道具在背包中的图标、名称、描述显示没有在 Play Mode 里看过；Buff 图标没有接入面板；大瓶星屑药剂的回复效果要等 #28。这些图标按 `.gitignore` 不进仓库，克隆后需按 ASSET_RESTORE 补回。
