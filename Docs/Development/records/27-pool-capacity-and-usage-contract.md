# 缓存池数量上限与使用约定

2026-11-08，PoolMgr 与新增 PoolObj。

## 用户观察与目标

用户优化基础缓存池后要求检查，通过后更新文档并推送。目标是在复用空闲对象的基础上，为每种对象增加数量上限，并提供方便调试的场景层级整理开关。

## 用户提出的想法

- 每种预制件挂载 PoolObj，通过 maxNum 配置数量上限。
- 达到上限且没有空闲对象时，轮换使用最早借出的对象。具体对象的重置逻辑等实际接入时处理。
- isOpenLayout 用于开发调试，运行前设置，使用期间保持固定。当前不需要处理运行中切换。
- 缺少 PoolObj 属于开发配置错误，开发人员根据 LogError 补齐组件，当前不增加恢复处理。
- 对子弹等对象，命中和超时统一进入结束流程，由对象生命周期负责终止后续检测与回调，并保证每次借出只归还一次。

## 辅助分析与建议

Codex 核对了空闲栈、使用中列表和数量上限的分支。此前提出重复归还、运行中切换层级开关、漏挂组件后继续调用等风险，但没有在当前项目发现造成这些情况的实际调用链。用户明确上述使用约定后，这些防御性处理不作为当前缺陷或提交阻碍。

达到上限时，代码会把仍在使用的对象重新交给调用方。对已激活对象再次调用 SetActive(true) 不会重新触发 OnEnable。对象是否需要重播特效、重置位置或清理旧回调，由后续具体对象接入时确定，按用户决定延期。

## 实际采纳与用户调整

- 用户已独立实现 PoolData，内部使用 Stack<GameObject> 保存空闲对象，List<GameObject> 保存使用中的对象。
- GetObj 优先取空闲对象，空闲栈为空且使用中数量未达到上限时创建对象，达到上限时轮换列表首项到末尾。
- PoolObj 的默认 maxNum 为 50。PoolData 构造时读取组件配置，用户将组件检查移到了创建子池容器和登记使用中对象之前。
- 开启层级整理时创建 Pool 根节点及分类节点，归还对象停用并挂到分类节点，取出对象后解除父级。
- 保留现有归还逻辑，由调用方保证对象来自对应缓存池、名称与池键一致、组件配置完整、每次借出归还一次。ClearPool 的销毁行为仍按历史决定延期，当前只清字典并置空根引用。
