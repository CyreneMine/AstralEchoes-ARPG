## 辅助分析与建议（Claude Code）

### 原来代码里的隐含状态

- `EnemyAI` 用 `isWaiting`、`isFollowUp`、`isReturning` 三个 bool 加上 `health.isDead`，组合出巡逻、等待、追击、返回、死亡 5 个状态。攻击没有单独的状态，是在追击里进入攻击距离时调用 `TryAttack`。
- 读代码要在脑子里跑一遍：侦测分支里的 `if (isReturning) return;` 看起来多余，其实只在同一帧刚调用完 `LoseTarget()` 时成立，用来防止刚脱战又追回去（记录 33 里也讨论过）。
- `agent.isStopped = false` 写在两处，每多一种离开等待的方式就要多写一处。

### 结构

- **三层**：
  - 主人 `EnemyAI`：共享数据、生命周期、事件入口、`ChangeState`；
  - `StateMachine`：记住当前状态，按“旧状态 Exit → 换 → 新状态 Enter”切换，转发 Update；
  - 各个状态：自己的行为和切换条件。
- **组合，不是继承**：`EnemyAI` 已经继承 MonoBehaviour，C# 只能单继承；状态实现 `IState` 接口，表示“能被状态机驱动”这种能力。
- **为什么要 currentState**：`EnemyAI` 里的状态字段记的是“有哪些状态”，`currentState` 记的是“现在是哪一个”。它是接口类型，可以指向任何状态，调用时按实际对象执行，用多态代替原来的 bool 和 if。
- **数据放哪**：几个状态共用的留在 `EnemyAI`（`currentIndex`、agent、config），只有一个状态用的放进那个状态（`waitUntil` 放在等待，`startPos` 放在追击）。
- **生命周期**：Awake 里创建状态机和状态，Start 里切到巡逻。Awake 时 agent 可能还没取到，NavMeshAgent 也不一定已经放到导航网格上。
- **命名**：方法名要和做的事一致，所以有了 `MoveToCurrentPatrolPoint`、`NextPatrolIndex`，`HasArrived` 返回 bool。`Reset` 和 Unity 的消息函数同名，改为 `ResetAI`。

### Enter 和 Exit 的分工

- Exit 只撤销这个状态对共享对象做的临时修改。
- 能走是 agent 的默认状态，谁让它停下，谁负责在离开时恢复：等待、死亡（以后还有攻击）在 Enter 停下、Exit 恢复；巡逻、追击、返回不碰 `isStopped`。
- 巡逻设置的目的地不是临时修改，下一个状态会自己处理，所以巡逻的 Exit 是空的。

### 死亡与复用

- **死亡是一个状态**，由事件进入。死亡状态里没有切换条件，不响应游戏过程中的事件。
- **事件放在基类**：死亡发生在 `CharacterHealth`（`TakeDamage` 判断归零、`Dead()` 设置 `isDead`），通知也放在同一个地方，和 `OnHealthChange` 一样。`EnemyHealth` 和 `PlayerHealth` 只放各自特有的事：发奖励、全局广播。
- **复用靠重置方法**：出池时由调用方放好位置后调用重置方法，重置方法里 `ChangeState` 切回巡逻，会经过死亡状态的 Exit。不放在 OnEnable，因为 `PoolData.Pop()` 先 `SetActive(true)` 再把对象交给调用方设置位置。也不放在死亡状态的 Exit，原因有三：
  - Exit 拿不到出生位置；
  - 以后“原地复活”也会离开死亡状态，但不该被传送；
  - 生命、血条不属于 AI。
- **预制体没有巡逻路线**：场景里那只怪的 4 个巡逻点是在场景里拖的，预制体上是空引用，所以复用时还要传入巡逻路线。

### 审查中发现、已由用户修复的问题

1. 第一次切换时 `currentState` 是 null，调用 Exit 会抛空引用，改为 `?.`。
2. 初始切换写在 Awake 最前面，那时 agent 和 config 还没赋值，挪到 Start。
3. 子类没写构造函数（C# 的构造函数不继承）；`owner` 是 private，子类访问不了；还留着无参构造函数。改成 `: base(owner)`、protected，删掉无参构造函数，`EnemyState` 改为实现 `IState` 的抽象类。
4. 巡逻的下标加 1 后没有回绕，第 5 次走向巡逻点时访问 `patrolPoints[4]` 会越界。另外开局会先原地等 2 秒，到达判断也缺 `!pathPending`。
5. `InvertIsStopped` 用取反，结果取决于调用前的值，改为直接赋值；恢复导航放到等待的 Exit。
6. `UpdatePatrolPoint` 同时做“走向一个点”和“下标加 1”，但返回状态只需要走向当前点，于是拆成两个方法。
7. `ChangeState` 之后没有 return，一帧里可能连切两次。例如发现玩家和到达巡逻点在同一帧，下标会多加一次。
8. 追击里先攻击、后判断脱战，因“离出发点太远”脱战时会先出一刀，于是改为先判断脱战。
9. 玩家死亡后怪物停在原地：事件还在调用旧的 `LoseTarget()`，它改的 bool 已经没有状态在读，怪物仍在追击，下一帧又把目的地设回玩家（尸体）的位置。修法是写返回状态，事件入口切到返回。
10. 返回状态一度是空的（文件没有改动），脱战以后怪物会停在玩家最后所在的位置，补上了。
11. OnEnable 订阅了 `OnDeath`，OnDisable 里没有取消，接入对象池后会重复订阅，已补上。
12. 死亡状态 Exit 里的 TODO 写着“出池在这里切回巡逻”。照做的话，Exit 里调用 `ChangeState` 会再次执行死亡状态的 Exit，形成无限递归，所以删掉了这条 TODO。

### 被修正的说法（Claude Code）

- **示例漏写初始切换**：讲解时的示例只在 Awake 里创建状态，漏写了 Start 里切到初始状态。用户追问 `StateMachine` 的意义时补上了。
- **“Enter 和 Exit 成对”说得太宽**：准确的规则见上文“Enter 和 Exit 的分工”。用户原来“每个状态进入时自己设好”的写法也是一种一致的规则，Claude Code 曾说它“以后切到追击时怪会站着不动”，前提是追击的 Enter 不设置，说得太绝对。最后按“谁停谁恢复”实现，因为能避免用户指出的重复。
- **没有先查记录 33**：讨论“玩家死亡和复活时怎么响应”时，Claude Code 把记录 33 里用户已经决定过的事说成了新问题，之后更正。
- **步骤安排留下空档**：Claude Code 建议先让追击脱战后切回巡逻、第 5 步再写返回，又说追击里“玩家死亡就切到等待”的两行“在那之前暂时留着也行”，但没有说明删掉之前必须先改好事件入口，导致了上面第 9 个问题。这个临时做法还让“离出发点太远”这条脱战在返回状态写好之前不起作用：怪物刚切回巡逻，就因为玩家还在侦测范围内马上追回去。

### 运行中修改脚本导致的空引用

编辑器日志里多次出现成对的 `EnemyAI.cs:101` 和 `PlayerCombat.cs:16` 的 NullReferenceException。时间上都在“进入 Play Mode 后又重新编译”之后：重新加载程序集以后，没有序列化的 private 字段（如 `stateMachine`）变成 null，而 Awake 不会再执行。这不是代码缺陷。建议把 Preferences → General → Script Changes While Playing 改为 Recompile After Finished Playing，用户是否修改了没有记录。

## 实际采纳与用户调整

| 状态 | Enter | Update | Exit |
|---|---|---|---|
| `EnemyPatrolState` 巡逻 | 走向当前巡逻点 | 看到玩家就切追击；到达就切等待 | — |
| `EnemyWaitState` 等待 | 停下，记下结束时间，下标加 1（加 1 时回绕） | 看到玩家就切追击；时间到就切巡逻 | 恢复导航 |
| `EnemyChaseState` 追击 | 记下出发点 | 目的地设为玩家；超过 `loseRange`、离出发点超过 `maxRange` 或玩家死亡时切返回；在攻击距离内调用 `TryAttack` | — |
| `EnemyReturnState` 返回 | 走向当前巡逻点 | 到达就切等待；不侦测玩家 | — |
| `EnemyDeadState` 死亡 | 停下 | 无 | 恢复导航（复用时 `ResetAI` 切回巡逻会经过这里） |

**事件**
- `OnPlayerStateChange`：当前状态是追击时才切到返回。用户留了 TODO：以后的攻击状态也这样处理。
- `CharacterHealth.OnDeath`：在 `Dead()` 里设置 `isDead` 后广播。`EnemyAI` 在 OnEnable 订阅、OnDisable 取消，收到后切到死亡状态。

**和原来代码的行为差别**
1. **玩家死亡和复活**：现在只有追击中的怪物切到返回。原来是所有怪物都设为“返回中”，复活时附近巡逻的怪物在到达下一个巡逻点之前都看不到玩家，这个效果按用户决定不再保留。记录 33 的“复活后立刻挨打”仍然能避免，因为追击中的怪物在玩家死亡时就会走回去，不会守在尸体旁边。
2. **怪物死亡**：由事件进入死亡状态，原来是每帧读 `isDead`。
3. **下一个巡逻点**：目的地改在等待结束、进入巡逻时设置（原来在到达时设置），外部看到的行为相同。

**用户自己加的**
- 追击的脱战条件里加了 `PlayerIsDead()` 作为保险。玩家死亡时事件会当场把追击中的怪物切到返回，所以正常情况下用不到它。
- `EnemyObject.Spawn(pos, patrolPoints)`：回满生命、刷新血条，再调用 `EnemyAI.ResetAI`。`ResetAI` 依次做四件事：`Warp` 到出生点、换巡逻路线、下标归零、切回巡逻。
